## 1. One paragraph

Video Studio is a Hermes plugin (loopback host + its own studio app) with six rooms: **Films,
Assets, Script, Timeline, Generate** — and one engine per job: **HyperFrames** renders typed
shots, **ComfyUI on sparke** renders generative ones (MiniMax H3 is live and produced a real
5.2 s clip today), and **MLT/`melt`** renders a timeline. The script room turns an idea into
timed beats; the shot generator turns beats into compositions; the timeline can seed itself
from a film and render an edit. The end-to-end loop runs: **idea → beats → shots → render →
gate**, and today it produced a 24.0 s film that **passes all three gate checks** (`shippable: true`,
weakest second 4.48 % motion, −16.1 LUFS) and is shipped as
`/mnt/AllShare/dev/videos/hackathon-2026-11-11/aura-sound-made-visible-24s.mp4`.

## 5. The three new subsystems

### 5.1 Generation (ComfyUI)

- `video_studio/comfy.py` — client: `status()`, `submit()`, `wait()`, `download()`, `render()`.
  Parameters are substituted **by node `_meta.title`**, never by node id.
- `video_studio/comfy_api.py` — `GET /comfy/status`, `GET /comfy/models`,
  `POST /comfy/render {workflow, params, out}`. Host comes from `comfy.json` in the workspace,
  default `http://10.0.0.52:8188`.
- `~/Development/hewn-motion/workflows/h3-minimal.api.json` — **the working H3 graph** in API
  format (15 nodes): UNETLoader(H3 fp8) → CLIPLoader(qwen3vl 32b, type `minimax`) → 2× VAELoader
  (video/audio) → MiniMaxH3SigmaShift → MiniMaxH3ImageToVideo(width,height,length) → BasicGuider
  → KSamplerSelect(res_multistep) + BasicScheduler + RandomNoise → SamplerCustomAdvanced →
  VAEDecode + VAEDecodeAudio → CreateVideo(fps 24, audio) → SaveVideo.
- Cost reference: **768×448, 124 frames, 20 steps ≈ 192 s** on a GB10. 1344×768 (default) will
  be slower; measure before promising anything.
- The 135-node UI workflow on the box (`data/user/MiniMax_H3_CE_v0.2.json`) is **not** API format
  and has rgthree switches/subgraphs. Do not try to run it directly.

### 5.2 Script room

- `video_studio/script.py` — `draft()` (lane → JSON), `parse()` (validation), `to_film()`,
  `save()`. Rules: target ±6 % (min 1.5 s), 2–24 beats, ≥2 s per beat, ≤22 words per line, a
  spoken line required, no invented metrics in the brief.
- `video_studio/shotgen.py` — `write_shot()` (lane → one composition), `check()` (static
  contract), `write_all()`. Honours `beat["src"]`; strips prose/fences around `<template>`.
- Routes: `POST /script/draft`, `/script/check`, `/script/save`,
  `/script/{film}/shots`, `/script/{film}/build` (author + render).

### 5.3 Timeline

- `video_studio/ops.py` — pure operations over JSON state; `_pure()` guarantees no caller state
  is mutated; `normalize()` prevents overlaps and recomputes total; history stack for exact undo.
- `video_studio/timeline_api.py` — `GET /timeline/{film}`, `POST .../ops`, `.../undo`,
  `.../reset`, `.../from-film`, `.../render`, `GET .../video`.
- UI `studio/timeline.js` — lanes V1/V2/A1/A2, drag to move, edge-drag to trim, sync-from-film,
  undo, render. It follows the film selected in the left rail (`window.__studioFilm`).

### 5.4 Generated beats inside a cut (added after the first handoff)

A film can mix engines per beat: `"renderer": "html"` (HyperFrames composition) or
`"renderer": "comfy"` (MiniMax H3, no HTML at all).

- `video_studio/gen_beat.py` — beat → prompt, beat → legal frame count, and normalisation:
  any clip becomes **1920×1080 / 30 fps / exactly the beat duration / no audio**, then
  **graded to the brand** (`hue=s=0.28` + colour mixer to blue + light grain). H3 returns
  rainbow-coloured, perfectly clean frames; ungraded they look like an experiment dropped into
  the film rather than part of it.
- `POST /comfy/beat {film_id, beat_id}` — renders that beat on the GPU box and writes
  `renders/shots/<beat id>.mp4`, the same path a HyperFrames shot goes to. Assembly therefore
  does not care which engine made which beat.
- `POST /films/{fid}/assemble` — cuts every beat clip in order with MLT, attaches
  `renders/bed-<total>.wav` if present, **normalises the audio into −18…−14 LUFS**, and writes
  `renders/<fid>-final.mp4`. Refuses (HTTP 400) and names the beats that have no clip.
- The gate now runs **four** checks: hook, motion, **audio**, legibility. It caught a real
  defect the first time it ran: `melt` mixes a bed at file level, so a −36.6 LUFS bed produced a
  cut that plays as silence on most systems. Measured before/after: **−36.56 → −16.06 LUFS**.

Measured on 2026-11-10 (GB10, H3 fp8, 20 steps):

| job | frames | wall |
|---|---|---|
| one 7 s beat at 768×448 | 169 | **263 s** total, H3 inference + fetch + normalise |
| assemble 4 clips + bed, 24 s | — | 96–102 s (melt + audio normalise) |
| gate (4 checks, incl. loudness) | — | ~10 s |

Result: `films/aura-mixed.json` (3 typed beats + 1 generated beat) → `aura-mixed-final.mp4`,
24.0 s, gate **shippable**, shipped to AllShare as `aura-mixed-engines-24s.mp4`.

### 5.5 Music from Music Studio, and cheap drafts (added later the same night)

- `video_studio/music.py` reads Music Studio's take store **read-only**
  (`~/.hermes/plugin-data/hermes-music-studio/<project>.json` + `<take>.wav`), and cuts a bed
  from any take: start offset, fades, loop if the take is shorter than the film, 48 kHz stereo.
- `POST /films/{id}/music {track_id, start, fade_in, fade_out}` stores a pointer in the film;
  assembly uses it in preference to a loose `bed-*.wav`. `track_id: "none"` clears it.
- The hand-written sine bed was retired: it measured −36.6 LUFS and sounded like a buzz. Real
  takes measure −15…−18 LUFS and normalise to −14.5…−16 without artefacts.
- `POST /films/{id}/drafts {variants:[quiet,cinematic,kinetic]}` builds each variant as its own
  mini-project inside `film/drafts/<film>-<variant>/` (HyperFrames only renders compositions
  mounted from that project's `index.html`), renders it in one pass at 15 fps draft settings,
  scales to 960×540, and lays the film's music underneath at −16 LUFS.
- Cross-promotion is mutual and discoverable: `/api/neighbour/music-studio` (this plugin) and
  `/api/studio/neighbour/video-studio` (Music Studio) each read the other's `studio-host.json`
  and health-check it. Both UIs have a button to open the other; neither hard-codes a port.

Measured: three drafts of a 24 s film ≈ 4 minutes total; each ~1 MB at 960×540, 24.0 s, −14.5 LUFS.

### 5.6 Real footage, stills, and the Production room (the glue)

- `video_studio/capture.py` + `capture.js` — scripted browser capture of any URL: steps of
  click / type / scroll / move, a synthetic cursor drawn and animated so the recording shows
  someone using the thing, then 1080p30 H.264 with no audio. Measured: 11-step studio
  walkthrough → **18.6 s, 1920×1080, 0 console errors**, 924 KB.
  *Why not a desktop recorder:* the host is Wayland/KDE with no `wf-recorder`, `grim` or
  `xdg-desktop-portal`, and Electron windows capture black. The browser route is clean,
  reproducible, and shows only the app — no other sessions, no notifications.
- `POST /stills/scan` — ingests every image in `assets/stills/` as a normal asset (content hash,
  proxy, thumbnail), optionally turning each into a slow-push clip. Stills come from an image
  model outside this plugin: the ComfyUI box has **no image checkpoint installed** (only H3,
  Wan I2V and Music3), so the hand-off is a folder. Verified with a Krea-3 2K still.
- `POST /assets/import` — same intake, by explicit path (a capture, a generated frame).
- **Production room** — eight ordered stages: beats → typed shots → real footage → generated
  b-roll (H3) → stills → music → directions (drafts) → cut. Each stage calls the endpoint that
  already exists; there is no second implementation behind the UI.

### 5.7 Gate changes this session (each one caught a real defect)

| Change | Why |
|---|---|
| `check_audio` (loudness −18…−14 LUFS, TP ≤ −1) | a −36.6 LUFS cut passed as "shippable" |
| `check_hook` measures the picture area, not the matte | a correctly letterboxed film was failed for being dark |
| `check_hook` accepts dark-but-lit frames (lit ≥ 2 %, peak ≥ 170) | mean brightness punishes a deliberately dark brand |
| `_is_finalised` probe | a half-written render reported "no audio stream" instead of "still rendering" |

### 5.8 A beat made of real footage (the first cut that isn't all HTML)

`POST /films/{fid}/beats/{bid}/footage {capture, start, seconds}` turns a capture into a beat:
trim, scale 1.04× and **slow pan** (a screen recording is mostly still, and the motion check is
per second), letterbox bars + soft vignette to match the cinematic treatment, a lift
(`brightness=0.05`) because a dark UI under a strong vignette measures 3/255, light grain, no
audio. Writes `renders/shots/<beat id>.mp4` and records `renderer: "capture"` on the beat.

Applied to `aura-sound-made-visible`: beat 2 (`shot-listens-to-anything`, 6 s) is now the studio
itself playing the film. Gate: hook 14.9 luma (lit 4.1 %, peak 244), motion weakest **4.21 %**
(was 0.06 % before the pan), audio −14.5 LUFS, type 34 px → **shippable**.

Lesson worth keeping: every "cinematic dressing" step (letterbox, vignette, dark palette) costs
brightness, and the gate is what notices. Dress the frame, do not bury the picture.

## 7. How a film is made now (the loop that works)

```bash
# 1. idea -> beats (lane)
POST /api/script/draft {"idea": "...", "seconds": 24, "shots": 4}
# 2. write films/<id>.json + .script.json
POST /api/script/save  {"title": ..., "beats": [...], "seconds": 24}
# 3. author compositions (one lane call per beat, ~10-20 s each)
POST /api/script/<id>/shots {"only_missing": true}
# 4. render (HyperFrames CLI, 24 s ≈ 35-55 s)
cd ~/Development/hewn-motion/film && npx --yes hyperframes@0.9.26 render --quality draft \
   --output ../renders/<id>-raw.mp4
# 5. sound: a bed exists at renders/bed-24.wav; mux + normalise
ffmpeg -y -i ../renders/<id>-raw.mp4 -i ../renders/bed-24.wav -c:v copy -c:a aac \
   -shortest -filter:a "loudnorm=I=-16:TP=-1.5:LRA=11" ../renders/<id>-final.mp4
# 6. gate
POST /api/films/<id>/gate
```

## 8. Known defects (read before promising anything)

1. **FIXED — the last-second motion.** Root cause was not design: generated shots place their
   "persistent motion" tweens **without a position argument**, so GSAP appends them *after* the
   existing chain (a 6 s scene would animate from 1.7 s to 7.7 s, or never at all), and two of
   the four files had no `// Ensure frame 0` anchor so earlier repairs silently did nothing.
   What actually fixed it: a **whole-frame slow zoom** — `tl.fromTo("#root", {scale:1},
   {scale:1.035, duration: <scene seconds>, ease:"none"}, 0)` — injected into every shot.
   Profile went from `[.. 10:0.08 17:0.12 ..]` to **every second ≥ 4.96 %**. The generic tool is
   `tools/fix_motion.py` + `tools/fix_sweep.py`; the pattern belongs in `shotgen.CONTRACT`:
   *motion tweens must carry an explicit time position*. 
2. **`hyperframes check` blocks rendering** when there are warnings (contrast, first_frame_empty,
   film_silent). Render with `--quality ...` still proceeds if lint is not `--strict`; the gate
   is the authority. Fix contrast by lightening accent text (`#6da2f8` passes on `#0b0d10`).
3. **Audio is a manual mux.** The film pipeline has no bed; `renders/bed-24.wav` was generated
   ad hoc (two sines + pink noise, lowpass, fades). Move this into `tools/audio.py`.
4. **H3 output is 768×448**, not 1080p. Frames must be upscaled (or generated at 1344×768) before
   they can sit beside typed shots in a 1080p film.
5. **Shot naming and prose wrappers were bugs** (produced `shot-shot-*.html`, and files starting
   with "Here's a composition…"). Both fixed in `shotgen.py`; four files were repaired by hand
   today. Re-running `write_all` on an existing film will skip them (`only_missing`).
6. **Timeline and Films keep separate state.** `from-film` seeds V1 once; editing the timeline
   afterwards does not write back to `films/<id>.json` (by design for now — decide which is
   authoritative before changing it).
7. **Detached shell renders die; the plugin's job endpoint does not.** A `terminal(background=true)`
   HyperFrames render was killed when its shell exited (twice). `POST /films/{id}/render` does
   work — measured: `state done in 155 s`, 720 frames, exit clean — but it runs with 2 workers
   vs the foreground renderer's 3–6, so it is ~2–4× slower (34 s → 155 s on the same 24 s film).
   Prefer foreground for authoring, the job endpoint for anything that must survive.
